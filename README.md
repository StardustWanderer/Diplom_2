# Diplom_2 — API-тесты Stellar Burgers

Автоматизированные API-тесты сервиса [Stellar Burgers](https://qa-stellarburgers.education-services.ru/) в рамках второго дипломного проекта.

Тесты написаны на Java с использованием Maven, JUnit 4 и REST Assured. Для сбора результатов тестовых прогонов и формирования отчётов используется Allure Report.

## Технологии

- **Java 11** — язык разработки.
- **Maven** — управление зависимостями и запуск тестов.
- **JUnit 4.13.2** — тестовый фреймворк.
- **REST Assured 5.4.0** — отправка HTTP-запросов и проверка ответов API.
- **Allure 2.29.0** (`allure-junit4`, `allure-rest-assured`) — сбор результатов тестирования и добавление информации об HTTP-запросах и ответах в отчёт.
- **AspectJ Weaver 1.9.25.1** — поддержка аннотаций Allure `@Step` во время выполнения тестов.
- **JavaFaker 1.0.2** — генерация тестовых данных.
- **Gson 2.13.2** — сериализация Java-объектов в JSON.
- **Lombok 1.18.46** — генерация геттеров, сеттеров и конструкторов моделей.
- **Maven Surefire Plugin 3.2.5** — запуск тестов JUnit 4 и настройка интеграции с Allure.

## Требования к окружению

Перед запуском убедитесь, что установлены:

- JDK 11;
- Apache Maven.

Allure CLI необходим только для локального просмотра результатов тестирования в виде HTML-отчёта. Его установка и версия отдельно в `pom.xml` не задаются.

## Запуск тестов

Из корневой папки проекта выполните:

```bash
mvn clean test
```

Команда очищает предыдущие результаты сборки и запускает тесты.

Результаты Allure сохраняются в каталоге:

```text
target/allure-results
```

## Отчёт Allure

Чтобы сформировать и открыть отчёт в браузере, выполните:

```bash
allure serve target/allure-results
```

Команда создаёт временный HTML-отчёт и открывает его в браузере.

Каталог `target/allure-results` содержит исходные результаты тестового прогона и вложения, необходимые для формирования отчёта. В соответствии с требованиями проекта результаты прогона прилагаются к репозиторию.

## Покрытие тестами

### Регистрация пользователя

Проверяются следующие сценарии:

- успешная регистрация нового пользователя;
- повторная регистрация уже зарегистрированного пользователя;
- регистрация без обязательного поля `email`;
- регистрация без обязательного поля `password`;
- регистрация без обязательного поля `name`.

Проверки отсутствующих обязательных полей реализованы с помощью параметризованного теста JUnit 4.

### Авторизация пользователя

Проверяются следующие сценарии:

- успешный вход под ранее зарегистрированным пользователем;
- попытка входа с несуществующим email;
- попытка входа с неверным паролем.

Для проверки авторизации перед тестами создаётся пользователь с динамически сгенерированными учётными данными.

### Создание заказа

Проверяются следующие сценарии:

- создание заказа с авторизацией и корректными ингредиентами;
- создание заказа без авторизации;
- попытка создать заказ без ингредиентов;
- попытка создать заказ с невалидным хешем ингредиента.

Для формирования корректного заказа тесты предварительно отправляют `GET /api/ingredients` и получают актуальные идентификаторы ингредиентов из ответа API.

**Примечание:** в тесте создания заказа без авторизации ожидается HTTP 200 и `success: true`. Это ожидаемое поведение, согласованное с куратором проекта.

### Назначение пакетов

- **`config`** — базовый URL сервиса и пути API.
- **`data`** — генерация тестовых данных пользователей с помощью JavaFaker.
- **`models`** — модели тел HTTP-запросов, преобразуемые в JSON.
- **`steps`** — методы отправки HTTP-запросов. Общие настройки REST Assured, сериализация объектов и интеграция с Allure находятся в `BaseSteps`.
- **`tests`** — тестовые сценарии и проверки ответов API. `BaseTest` содержит общую очистку тестовых данных.

## Используемые эндпоинты

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/ingredients` | Получение ID ингредиентов для создания заказа |
| `POST` | `/api/auth/register` | Регистрация пользователя |
| `POST` | `/api/auth/login` | Авторизация пользователя |
| `DELETE` | `/api/auth/user` | Удаление тестового пользователя |
| `POST` | `/api/orders` | Создание заказа |

Базовый URL задаётся в `praktikum.config.Urls`, а пути эндпоинтов — в `praktikum.config.ApiEndpoints`.

## Архитектура тестов и работа с тестовыми данными

Для организации API-тестов используются отдельные классы, разделяющие подготовку данных, формирование запросов и проверки ответов.

- **Модели запросов** описывают структуру JSON-тел запросов.
- **Steps-классы** инкапсулируют HTTP-запросы к API и возвращают объекты `Response`.
- **BaseSteps** содержит общую спецификацию REST Assured, сериализацию Java-объектов в JSON и фильтр Allure.
- **BaseTest** содержит общую логику очистки тестовых данных.

Тестовые пользователи создаются динамически. После регистрации сохраняется `accessToken`, который используется для удаления тестового пользователя после завершения теста.

В `BaseTest` метод с аннотацией `@After` выполняет попытку удаления пользователя, если токен авторизации был получен.

## Использованные подходы

- параметризованное тестирование — проверка регистрации без каждого из обязательных полей;
- генерация динамических тестовых данных — создание уникальных пользователей;
- повторное использование подготовительных методов и общей спецификации запросов;
- проверка HTTP-статусов, полей и значений JSON-ответов;
- разделение тестовых сценариев и методов взаимодействия с API;
- автоматическая очистка тестовых пользователей после выполнения тестов;
- интеграция Allure для документирования тестовых сценариев и HTTP-взаимодействий.
