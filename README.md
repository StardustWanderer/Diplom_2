# Diplom_2 — API-тесты Stellar Burgers

Автоматизированные API-тесты сервиса [Stellar Burgers](https://stellarburgers.education-services.ru/) в рамках дипломного проекта.

Тесты написаны на Java с использованием Maven, JUnit 4 и REST Assured. Для сбора результатов и просмотра тестовых прогонов используется Allure Report.

## Технологии

- **Java 11** — язык разработки.
- **Maven** — управление зависимостями и запуск тестов.
- **JUnit 4.13.2** — тестовый фреймворк.
- **REST Assured 5.4.0** — отправка HTTP-запросов и проверка ответов API.
- **Allure Java-интеграции 2.29.0** (`allure-junit4`, `allure-rest-assured`) — сбор результатов тестов и добавление информации о запросах в отчёт. Версия Allure CLI отдельно в `pom.xml` не задана.
- **Allure REST Assured** — добавление информации об HTTP-запросах и ответах в отчёт.
- **JavaFaker** — генерация тестовых данных.
- **Gson** — поддержка сериализации и работы с JSON.
- **Lombok** — генерация геттеров, сеттеров и конструкторов моделей.

## Требования к окружению

Перед запуском убедитесь, что установлены:

- JDK 11;
- Apache Maven;
- Allure CLI — для локальной генерации и просмотра HTML-отчёта.

## Запуск тестов

Из корневой папки проекта выполните:

```bash
mvn clean test
```

Команда очищает предыдущие результаты сборки и запускает тесты. Сырые результаты Allure сохраняются в каталоге `target/allure-results`.

## Allure-отчёт

Сгенерированный HTML-отчёт Allure включён в репозиторий в папке `test-report/` как часть сдаваемого проекта. Главная страница отчёта — `test-report/index.html`.

Чтобы обновить отчёт после нового запуска тестов, сначала выполните `mvn clean test`, затем сгенерируйте HTML-отчёт в корневую папку `test-report`:

```bash
allure generate target/allure-results --clean -o test-report
```

Открыть сформированный отчёт локально в браузере можно командой:

```bash
allure open test-report
```

## Покрытие тестами

### Регистрация пользователя

- успешная регистрация нового пользователя;
- повторная регистрация уже зарегистрированного пользователя;
- регистрация без обязательного поля `email`;
- регистрация без обязательного поля `password`;
- регистрация без обязательного поля `name`.

Проверки отсутствующих полей реализованы параметризованным тестом JUnit 4.

### Авторизация пользователя

- успешный вход под ранее зарегистрированным пользователем;
- попытка входа с неверными учётными данными.

### Создание заказа

- создание заказа с авторизацией и корректными ингредиентами;
- создание заказа без авторизации;
- попытка создать заказ с пустым списком ингредиентов;
- попытка создать заказ с невалидным хешем ингредиента.

Для формирования корректного заказа тесты получают актуальные ID ингредиентов через `GET /api/ingredients`. Тестовые пользователи генерируются динамически.

### Назначение пакетов

- **`config`** — базовый URL сервиса и пути API.
- **`data`** — генерация тестовых данных пользователей.
- **`models`** — модели тела запросов, которые REST Assured сериализует в JSON.
- **`steps`** — методы отправки HTTP-запросов. Общие настройки REST Assured и интеграция с Allure находятся в `BaseSteps`.
- **`tests`** — тестовые сценарии и проверки ответов API. `BaseTest` содержит общую очистку: после теста выполняется попытка удалить пользователя, если сохранён его токен авторизации.

## Используемые эндпоинты

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/ingredients` | Получение ID ингредиентов для заказов |
| `POST` | `/api/auth/register` | Регистрация пользователя |
| `POST` | `/api/auth/login` | Авторизация пользователя |
| `DELETE` | `/api/auth/user` | Удаление тестового пользователя |
| `POST` | `/api/orders` | Создание заказа |

Базовый URL задаётся в `praktikum.config.Urls`, а пути эндпоинтов — в `praktikum.config.ApiEndpoints`.

## Очистка тестовых данных

В `BaseTest` используется метод с аннотацией `@After`. Если во время теста был сохранён `accessToken`, после завершения теста выполняется запрос на удаление пользователя. Это помогает не оставлять тестовые аккаунты на сервере.
